# 목업 지원자 데이터셋

평가용 공고 2건에 대해 공고당 6명(완벽 2 · 부분 3 · 미스매치 1), 모두 12명의 목업 이력서다.

- **형식**: 이 JSON은 **이력서 전처리 결과** 형식이다. 실제 이력서(PDF·DOCX·HTML·MD·이미지)는 이력서 전처리 단계가 같은 형식으로 만든다 — 설계만 있고 구현하지 않았다 ([ADR-0016](../docs/adr/0016-candidate-model-and-mock-dataset.md)). 목업은 그 전처리를 손으로 대신한 결과이고, `source.method`가 `mock`이다.
- **`meta`는 평가 전용**이다. 대상 공고, 의도 라벨, 설계 의도, 의도한 판정을 담는다. 렌더링·판정·점수 계산은 `meta`를 읽지 않는다 (테스트로 보장). `jobfit match` 결과 표에 라벨을 표시만 하고, 의도 대비 순서·점수 구간·판정 일치율을 함께 출력한다.
- **민감 정보 필드 없음**: 장애·보훈 여부, 생년·나이, 성별 필드를 두지 않는다 ([ADR-0018](../docs/adr/0018-statutory-preferences-not-scored.md)). 병역은 국내 입사지원서의 일반 항목이라 둔다.

## 설계 의도 — 각자 다른 이유로 점수가 갈리게

## 필드

| 필드 | 설명 |
|---|---|
| `education[]` | `level`(high_school·associate·bachelor·master·phd), `status`(graduated·expected·enrolled·dropped), `graduation` — 학력 서열은 코드가 비교 |
| `experiences[]` | `start`·`end`(YYYY-MM, `null`=재직 중) — 경력 연수는 코드가 겹침 병합해 계산 |
| `declarations[]` | 입사지원서의 자기 신고 항목 ("2027년 1월 입사 가능", "야간근무 가능") |
| `skills[]` | 기술·키워드. 여기에만 있는 내용은 판정에서 "부분"을 넘지 않는다 |
| `source` | 출처 (`mock` / `upload` / `ats`, 원본 형식, 파일 해시) — 스코어링은 읽지 않음 |
| `meta.expected[]` | 의도한 판정 `{requirement: 요건 문구 일부, status}` — 판정 일치율 측정용 |
