# ADR-0002: CLI·API·UI는 같은 서비스를 호출하는 얇은 어댑터

- 상태: 채택
- 날짜: 2026-10-12
- 관련 스펙: 전체

## 맥락

실행은 CLI 또는 API 하나로 가능해야 하고, 결과를 확인할 간단한 UI가 필요하다. 세 진입점이 각자 로직을 가지면 동작이 어긋나고 테스트가 세 배가 된다.

## 결정

```
CLI ──┐
      ├──▶ 서비스 함수 (crawler / preprocessing / scoring)
API ──┘
UI ──▶ API
```

- 비즈니스 로직은 서비스 함수에만 둔다. 서비스 함수는 설정·네트워크 클라이언트·LLM 같은 의존성을 **인자로 주입**받는다.
- CLI는 인자 파싱과 출력만, API는 요청/응답 변환과 오류→상태 코드 매핑만 한다.
- UI는 API만 호출한다 (서버 렌더링 없음, 정적 페이지).
- 도입 시점: CLI는 스펙 01부터 단계별 명령으로, API·UI는 보여줄 결과가 생기는 단계에서.

## 검토한 대안

- **API 서버 하나만 두고 CLI는 API 클라이언트로** — 개발 중 매번 서버를 띄워야 하고, 오프라인 배치 실행이 불편하다.
- **UI에서 서비스 직접 호출 (Streamlit 등)** — 빠르지만 CLI·API와 별개 실행 경로가 생긴다.

## 결과

- 얻는 것: 서비스 함수만 테스트하면 세 진입점의 동작이 같다. 어댑터 테스트는 얇게(호출·출력·오류 매핑) 유지한다.
- 감수하는 것: 서비스 함수의 의존성 주입 때문에 시그니처가 다소 길어진다.
