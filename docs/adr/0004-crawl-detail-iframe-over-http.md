# ADR-0004: 사람인 상세 본문은 iframe 문서를 HTTP로 직접 수집

- 상태: 채택 (실 페이지 검증 조건부 — 스펙 01 관찰 H1)
- 날짜: 2026-10-12
- 관련 스펙: 01

## 맥락

- 공식 Open API는 쓰지 않는다. 브라우저가 받는 것과 같은 HTML을 받아 파싱한다.
- 사람인 공고 페이지(`/zf_user/jobs/relay/view?rec_idx=`)의 상세 본문은 별도 iframe 문서로 로드되는 것으로 알려져 있다. 메인 페이지 HTML만으로는 본문 이미지를 얻지 못한다.
- 대상은 본문이 이미지인 공고다. 필요한 것은 이미지 URL과 원본 바이트다.

## 결정

- 공고 페이지(view)와 상세 iframe 문서(view-detail)를 **httpx로 직접 요청**한다.
  - view: 원문 보존, 제목 메타데이터, 이후 요청의 Referer
  - view-detail: 본문 이미지 URL 추출 대상
- 브라우저 User-Agent와 Referer를 붙이고, 요청 사이에 간격(기본 1.5초)을 둔다.
- 경로·셀렉터는 상수로 두고, 구현 계획의 수동 태스크에서 실제 페이지로 검증한 뒤 확정한다. 검증 결과가 다르면 이 ADR을 갱신(또는 대체)한다.

## 검토한 대안

- **Playwright 등 헤드리스 브라우저** — JS 렌더링이 필요한 경우를 다 처리하지만 무겁고 느리며, 이미지형 공고의 본문은 정적 `<img>`라 필요 이상이다. iframe 직접 요청이 실패할 때의 대안으로 남긴다.
- **공식 Open API** — 사용하지 않기로 한 제약.
- **메인 페이지만 파싱** — 본문이 iframe에 있으면 이미지를 얻을 수 없다.

## 결과

- 얻는 것: 가볍고 빠르며, `MockTransport`로 전체 수집 로직을 오프라인 테스트할 수 있다.
- 감수하는 것: 사이트 구조 변경에 취약하다. → 셀렉터를 상수 한 곳에 두고, 실제 HTML을 fixture로 저장해 회귀 테스트한다. 운영 구조에서는 직접 수집하지 않는다(아키텍처 문서 "운영 시 데이터 유입").
