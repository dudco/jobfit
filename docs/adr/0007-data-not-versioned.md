# ADR-0007: `data/`(수집·처리 산출물)는 버전 관리하지 않는다

- 상태: 채택
- 날짜: 2026-10-12
- 관련 스펙: 01
- 관련 ADR: [0005](0005-origin-snapshot.md)의 "결과 — 원본 커밋 여부" 항목을 확정

## 맥락

[ADR-0005](0005-origin-snapshot.md)는 공고 원본을 스냅샷으로 보존하기로 했고, 그 원본을 레포에 커밋할지는 "관찰 후 재검토"로 남겨 두었다. 실제 수집 결과, 공고 1건의 스냅샷은 공고 페이지 HTML(약 0.4–0.5MB)과 원본 이미지(0.4–1.8MB)를 포함한다.

## 결정

`data/` 전체를 `.gitignore`에 넣는다. 스냅샷은 로컬에서만 보존하고, 필요하면 `jobfit crawl`로 다시 만든다.

회귀 테스트에 필요한 최소한의 원본은 `tests/fixtures/`에 따로 둔다 (예: 상세 iframe HTML — 이미지 태그와 메타 텍스트만 있는 수 KB 파일).

## 검토한 대안

- **`data/` 전체 커밋** — 키 없이·사이트 접속 없이 전 과정을 재현할 수 있지만, 공고 이미지는 채용 플랫폼·기업의 저작물이고 용량이 계속 늘어난다. 공개 레포에 원본을 재배포하는 것은 운영 구조에서 지향하는 "서비스가 원본을 쌓지 않는다"는 방향과도 맞지 않는다.
- **일부(매니페스트만) 커밋** — 매니페스트만으로는 재현이 안 되고, 원본 URL이 그대로 노출된다.

## 결과

- 얻는 것: 레포가 가볍고, 원본 재배포 문제가 없다.
- 감수하는 것: 다른 환경에서 2·3단계를 재현하려면 먼저 `jobfit crawl`로 스냅샷을 다시 받아야 하고, 그 사이 공고가 마감·변경되면 같은 원본을 얻을 수 없다. → 단계별 테스트는 `tests/fixtures/`의 작은 원본으로 돌고, 공고 원본에 의존하는 결과(추출 조건·점수)를 재현 가능하게 남기는 방법은 2·3단계 스펙에서 정한다.
