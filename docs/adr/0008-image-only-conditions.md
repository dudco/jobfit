# ADR-0008: 매칭 조건은 공고 이미지에서만 얻는다 (페이지 텍스트·숨김 키워드 미사용)

- 상태: 채택
- 날짜: 2026-10-12
- 관련 스펙: 01 (관찰 9장), 02·03 (적용 대상)

## 맥락

스펙 01 수집 결과, 사람인 상세 본문(`.user_content`)에는 공고 이미지 외에 `font-size:0`으로 숨긴 텍스트 블록이 있다. 내용은 공고 제목과 사람인 직무 카테고리 경로 수십 줄이다.

```
회계·세무·재무 > 직무·직업 > 재무
인사·노무·HRD > 담당분야 > 인사기획
영업·판매·무역 > 직무·직업 > 해외영업
…
```

이 텍스트는 이미 기계가 읽을 수 있는 형태라, 직무 매칭에 바로 쓰고 싶은 유혹이 있다. 공고 페이지 제목(`og:title`)이나 사람인 페이지의 다른 텍스트(근무지, 경력 조건 요약 등)도 마찬가지다.

## 결정

**전처리(②)와 스코어링(③)에 쓰는 공고 조건은 공고 본문 이미지를 파싱한 결과만으로 만든다.**

- 쓰지 않는 것: 숨김 키워드 블록, 공고 페이지 HTML의 텍스트(제목·요약 정보 포함), 사람인의 분류 메타데이터
- 스냅샷의 `view.html`, `detail.html`은 원본 보존·추적용으로만 남긴다 ([ADR-0005](0005-origin-snapshot.md)).
- `title`은 사람이 공고를 식별하는 표시용으로만 쓴다 (CLI 목록, UI 제목).
- 전처리 단계의 입력은 스냅샷의 `images` 목록으로 한정한다. HTML 파일을 읽는 코드를 전처리·스코어링 모듈에 두지 않는다.

## 근거

1. **요구사항과의 정합** — 이 시스템의 핵심 요구사항은 "이미지로 된 공고를 파싱해 조건을 구조화하고, 그 추출값을 매칭 조건으로 바로 쓰는 것"이다. 페이지에 이미 있는 텍스트로 조건을 채우면 이미지 파싱이 우회되고, 파싱 품질이 결과에 반영되지 않는다.
2. **출처의 성격** — 숨김 블록은 기업이 작성한 공고 내용이 아니라 플랫폼이 검색용으로 붙인 분류다. 실제로 S-OIL 사무직 공고에는 "영업·판매·무역 > 해외영업", "제약영업", "자동차영업" 등 공고와 무관한 카테고리가 대량으로 들어 있어, 조건으로 쓰면 노이즈가 된다.
3. **일반화** — 운영 구조에서는 공고가 고객사 업로드·연동으로 들어온다 (아키텍처 문서 "운영 시 데이터 유입"). 그 경로에는 사람인 숨김 블록이 없다. 사람인 전용 텍스트에 기대는 로직은 다른 출처에서 동작하지 않는다.
4. **판단의 재현성** — "이 조건은 이미지의 어느 부분에서 왔는가"를 항상 추적할 수 있어야 근거를 설명할 수 있다. 출처가 이미지 하나로 고정되면 근거 추적이 단순해진다.

## 검토한 대안

- **숨김 키워드를 직군 분류 보조 신호로 사용** — 직군 판별이 쉬워지지만, 위 2·3번 문제(노이즈, 출처 종속)와 1번(이미지 파싱 우회)이 그대로 남는다.
- **페이지 텍스트를 이미지 파싱 결과의 검증용으로 사용** — 교차 검증 아이디어는 유효하지만, 검증 신호가 노이즈가 많은 분류 데이터라 이득이 작고, 이미지 외 정보가 결과에 섞일 여지를 만든다.

## 결과

- 얻는 것: 결과 품질이 이미지 파싱 품질을 그대로 드러낸다. 출처와 무관하게 같은 파이프라인이 동작한다. 조건의 근거가 항상 이미지 위치로 추적된다.
- 감수하는 것: 쉽게 얻을 수 있는 구조화 정보를 버린다. 이미지 인식이 실패하면 보완할 수단이 없다 → 전처리 스펙(02)에서 이미지 분할·확대 등 인식 품질 확보 방법을 다룬다.
- 후속: 전처리·스코어링 코드는 스냅샷의 `images`만 입력으로 받는다는 것을 테스트로 고정한다 (스펙 02에서 정의).
