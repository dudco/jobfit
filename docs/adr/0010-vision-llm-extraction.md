# ADR-0010: 공고 이미지 읽기는 비전 LLM으로 한다 (OCR 엔진·규칙 기반 미채택)

- 상태: 채택 (스펙 02 실험 X1–X4로 검증 조건부)
- 날짜: 2026-10-12
- 관련 스펙: 02

## 맥락

공고 이미지에서 요건을 뽑는 일은 **읽기**(이미지 → 글자)와 **이해**(글자 → 구조)로 나뉜다. 평가용 공고 두 건만 봐도 형태가 크게 다르다.

| | 공고 A (S-OIL) | 공고 B (오리온) |
|---|---|---|
| 크기 | 860×3170 | 720×1890 |
| 요건 위치 | "지원자격" 목록 + 병합 셀 "모집분야" 표(분야·세부직무·전공·근무지) | 4열 "모집 내용" 표(업무내용 및 자격요건 / 우대사항 / 근무지역) |
| 필수/우대 구분 | 목록 안 "기타 우대사항" 하위 항목 | 열로 구분 |
| 글씨 | 작고 촘촘함, 배경 일러스트 | 작음, 빨간 표 머리 |

요구사항: 직군·레이아웃과 무관하게 동작해야 하고, 조건은 이미지에서만 얻으며(ADR-0008), 근거를 추적할 수 있어야 한다.

## 결정

- **읽기는 비전 LLM**으로 한다. 조각 이미지를 넣고 "보이는 글자를 그대로, 표는 마크다운 표로" 전사하게 한다.
- **이해는 텍스트 LLM**으로 한다 (ADR-0011).
- 이미지를 다루는 결정적인 작업(정규화, 분할)은 LLM이 아니라 **코드(Pillow)**로 한다 (ADR-0012).
- 기본 모델은 스펙 02 실험 X2 결과로 정해 이 ADR에 기록한다. 모델은 설정으로 바꿀 수 있게 한다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| **OCR 엔진 + 규칙** (Tesseract `kor` / PaddleOCR / EasyOCR + 섹션 제목 정규식·키워드 사전) | 장식 폰트·컬러 배경·작은 글씨에서 인식률이 떨어지고, 표 구조가 사라진다. 더 근본적으로, 섹션 이름·레이아웃이 공고마다 달라("지원자격" vs 표의 "자격요건" 열) 규칙을 공고마다 늘려야 한다 — 직군 무관 일반화와 충돌 |
| **OCR 엔진 + LLM 구조화** | 이해는 해결되지만, OCR 단계에서 잃은 표 구조·작은 글씨는 LLM이 복구할 수 없다 |
| **비전 LLM 1단계 (이미지 → 구조 JSON)** | ADR-0011 참고 — 중간 텍스트가 없어 근거 검증·오류 원인 구분이 안 된다 |
| **비전 LLM + OCR 교차 검증** | 이득 대비 설치·정렬 비용이 크다. 인용 검증(ADR-0011)으로 환각을 먼저 막고, 실험에서 읽기 오류가 많을 때 재검토 |

## 결과

- 얻는 것: 레이아웃·표·작은 글씨에 강하고, 공고가 늘어도 규칙을 추가하지 않는다.
- 감수하는 것:
  - **비용·외부 의존** → 조각 수가 적어(공고당 1–4) 비용이 작고, 응답 캐시(ADR-0014)로 반복 비용을 없앤다.
  - **비결정성·환각** → 전사 원문을 파일로 남겨 사람이 대조하고, 구조화 결과의 근거 인용을 코드로 검증한다.
  - **근거가 수치로 확인되지 않음** → 실험 X4(가능하면 Tesseract 기준선)로 OCR 대비 차이를 기록한다.
