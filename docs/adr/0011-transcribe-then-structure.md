# ADR-0011: 전사(읽기)와 구조화(이해)를 나누고, 결과를 코드로 검증한다

- 상태: 채택
- 날짜: 2026-10-12
- 관련 스펙: 02

## 맥락

비전 LLM으로 이미지를 다룰 때 두 가지 구성이 가능하다.

- 1단계: 이미지 → (비전 LLM) → 구조화된 요건 JSON
- 2단계: 이미지 → (비전 LLM) → 원문 텍스트 → (텍스트 LLM) → 구조화된 요건 JSON

이미지는 여러 조각으로 나뉠 수 있고(ADR-0012), "자격요건" 제목과 그 항목이 다른 조각에 걸칠 수 있다.

## 결정

1. **전사**: 조각마다 비전 LLM이 보이는 글자를 그대로 옮긴다. 조각 경계를 주석(`<!-- slice NN: … -->`)으로 남겨 `transcript.md`로 저장한다.
2. **구조화**: 전사 **전체**를 한 번에 텍스트 LLM에 넣고, 스키마(Structured Output)로 요건을 받는다. 요건마다 전사 텍스트의 근거 줄을 그대로 인용하게 한다.
3. **검증(코드)**: 인용이 전사에 실제로 있는지 확인하고, 없으면 `quote_not_found`로 표시한다. 인용 위치의 조각 주석으로 출처(이미지·조각 번호)를 채운다. id 부여, 중복 병합, 경고도 코드가 한다.

## 검토한 대안

- **1단계 (비전 LLM이 바로 JSON)** — 호출이 줄지만, 결과가 틀렸을 때 "글자를 잘못 읽었나, 해석을 잘못했나"를 구분할 수 없다. 근거 인용을 검증할 원문이 없어서 환각을 걸러낼 수단이 없다.
- **조각마다 구조화 후 병합** — 섹션 제목과 항목이 다른 조각에 걸치면 필수/우대를 잘못 매기고, 병합 시 중복 처리가 어렵다.

## 결과

- 얻는 것:
  - 전사 파일이 **사람이 검토 가능한 중간 산출물**이 된다 (원본 이미지와 나란히 대조).
  - 프롬프트를 고쳐 구조화만 다시 돌릴 때 비전 호출 비용이 들지 않는다 (캐시, ADR-0014).
  - 요건 → 인용 → 조각 → 원본 이미지로 근거를 끝까지 추적한다.
- 감수하는 것: 호출이 1회 늘어난다 (텍스트 모델이라 비용은 작다). 인용 검증은 "인용이 전사에 있다"까지만 보장하고, "전사가 이미지와 같다"는 사람의 대조·실험으로 본다.
