# ADR-0013: 요건은 "유형 고정 + 모집분야 범위" 구조로 표현한다

- 상태: 채택
- 날짜: 2026-10-12
- 관련 스펙: 02 (정의), 03 (사용)

## 맥락

- 특정 직군·스킬셋을 하드코딩하지 않고 구조적으로 확장 가능해야 한다.
- 한 공고에 모집분야가 여럿일 수 있고, 일부 요건은 특정 분야에만 해당한다. 공고 A(S-OIL)는 경영전략·재무·공정·설비기술 등 분야마다 전공 조건이 다르고, "엔지니어 직무 지원자는 직무 관련 자격증 우대"처럼 범위가 있는 우대사항이 있다.
- 공고에는 요건이 아닌 정보(근무조건, 전형, 제출서류, 복리후생)가 섞여 있다.
- 법정 우대(국가보훈·장애인)는 개인의 민감 속성이다.

## 결정

```
Requirement {
  priority:  must | preferred
  category:  experience | education | certification | language
             | skill | domain_knowledge | soft_skill | other      ← 고정된 "유형"
  text, normalized                                                   ← 내용은 데이터
  positions: [모집분야 이름]   (비어 있으면 전체 적용)
  min_years, min_education    (수치 비교가 필요한 유형만)
  sensitive: bool             (법정 우대 등)
  evidence: {quote, image_index, slice_index}
}
Position   { name, group, duties, location }
Conditions { employment_type, locations, schedule, others }          ← 점수에 쓰지 않음
```

- **일반화의 축은 스킬 사전이 아니라 요건 유형**이다. 회계든 생산이든 요건은 경력·학력·자격증·어학·기술·업무지식·태도·기타로 환원된다. 새 직군이 와도 코드는 그대로다.
- `job_family`는 자유 텍스트다 (enum으로 막지 않는다).
- 모집분야별 요건은 `positions`로 범위를 표시한다. 지원자를 어느 분야로 볼지는 스코어링(스펙 03)이 정한다.
- 근무조건은 지원자의 자격이 아니므로 `conditions`로 분리하고, 전형·제출서류·복리후생은 저장하지 않는다.
- "경력 무관"·"전공 무관"처럼 조건이 없음을 뜻하는 문구는 요건으로 만들지 않는다.
- 법정 우대는 추출하되 `sensitive: true`로 표시한다. 점수 반영 여부는 스펙 03에서 정한다.

## 검토한 대안

- **직군별 스킬 택소노미** — 직군이 늘 때마다 사전 유지보수, 사전 밖 요건 누락.
- **유형 없이 문구만** — 연차·학력처럼 수치 비교가 필요한 조건까지 매번 LLM이 판단해야 한다.
- **모집분야마다 별도 공고 조건으로 분리** — 공통 요건이 분야 수만큼 중복되고, 어느 분야 기준으로 평가할지가 데이터 구조에 고정된다.

## 결과

- 얻는 것: 코드 변경 없이 직군이 늘어난다. 다분야 공고를 한 구조로 표현한다. 민감 속성이 표시되어 스코어링에서 의도적으로 다룰 수 있다.
- 감수하는 것: 유형 분류를 LLM이 하므로 잘못 분류될 수 있다 → 정답 대비 유형 일치율을 실험 X3에서 측정한다.
