# ADR-0014: LLM 응답을 입력 해시로 디스크에 캐시한다

- 상태: 채택
- 날짜: 2026-10-12
- 관련 스펙: 02 (도입), 03 (재사용)

## 맥락

- API 예산이 제한되어 있다.
- 실험(분할 높이·모델 비교)과 프롬프트 수정으로 같은 공고를 여러 번 처리한다.
- 같은 입력에도 LLM 출력이 달라질 수 있어, 같은 결과를 다시 보려면 응답을 남겨야 한다.
- `data/`는 버전 관리하지 않는다 (ADR-0007).

## 결정

- 모든 LLM 호출을 `sha256(모델, 시스템 프롬프트, 사용자 입력, 이미지 바이트, 출력 스키마)` 키로 `data/cache/llm/{태그}-{해시16}.json`에 저장한다.
- 같은 키면 API를 호출하지 않는다 (API 키 없이도 동작).
- 캐시는 `LLM` 프로토콜을 감싸는 `CachedLLM`으로 구현해, 실제 클라이언트·테스트 대역과 독립적으로 테스트한다.
- 태그(`transcribe-{posting}-{slice}`, `structure-{posting}`)를 파일명에 넣어 어느 단계의 호출인지 보이게 한다.
- 캐시는 로컬 전용이다 (`data/` 아래, 커밋하지 않음).

## 검토한 대안

- **캐시 없음 + temperature 0** — 결정성을 완전히 보장하지 않고 비용이 반복된다.
- **결과(criteria.json)만 재사용** — 구조화 프롬프트만 바꿀 때도 비전 전사를 다시 해야 한다.
- **캐시를 레포에 커밋해 오프라인 재현** — 재현성은 좋지만 ADR-0007(원본·산출물 미커밋)과 충돌한다. 공고 이미지 전사문은 원본의 복제에 가깝다.

## 결과

- 얻는 것: 실험·프롬프트 반복 비용이 사실상 구조화 호출 1회로 줄어든다. 같은 입력에 같은 결과.
- 감수하는 것: 프롬프트 공백 하나만 바뀌어도 캐시 미스(의도된 동작). 다른 환경에서는 캐시가 없어 처음 실행 시 API 키가 필요하다.
