# ADR-0015: 매칭은 LLM이 요건별로 판정하고, 점수는 코드가 집계한다

- 상태: 채택
- 날짜: 2026-10-12
- 관련 스펙: 03

## 맥락

- 매칭 조건은 공고 이미지에서 뽑은 요건 목록이다 (ADR-0008, 0013). 직군이 정해져 있지 않아 요건 문구도 자유롭다 ("화공 전공", "야간근무 가능자", "인근거주자").
- 이력서는 같은 사실을 다른 말로 쓴다 ("화학생명공학과", "3조 2교대 근무"). 부정("야간근무 불가")과 대상 조건("남성의 경우")도 있다.
- 점수는 0~100이어야 하고, **사람이 읽을 수 있는 근거**가 함께 나와야 한다.
- 같은 입력에 같은 점수가 나와야 비교·회귀 테스트가 가능하다.

## 결정

1. **판정(LLM)**: 지원자 × 공고당 1회, 적용 요건마다 상태(`met`/`partial`/`unmet`/`unknown`/`not_applicable`), 이력서 **그대로 인용**, 한 줄 사유를 Structured Output으로 받는다. LLM은 숫자 점수를 내지 않는다.
2. **검증(코드)**: 인용이 이력서(줄 번호 렌더링)에 실제로 있는지 확인하고, 없으면 `unknown`으로 내린다.
3. **규칙 보정(코드)**: 학력 서열(`min_education`)과 경력 연수(`min_years`)는 코드가 계산한다. 연수는 LLM이 고른 관련 경력의 기간을 겹침 병합해 더한다. 규칙 결과가 LLM 상태보다 우선한다.
4. **집계·설명(코드)**: 가중 집계(ADR-0017)와 템플릿 설명. 요건별 기여 점수의 합이 최종 점수다.

스펙 02(ADR-0011)와 같은 원칙이다 — 언어 이해는 LLM, 검증·계산은 코드, 근거는 원문 인용으로 추적.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| **키워드·규칙 매칭** | 동의어·부정·대상 조건을 다루려면 직군별 사전이 필요하다 — 직군 무관 일반화와 충돌. 키워드 나열에 속는다 |
| **임베딩 유사도** | "비슷한 내용인가"는 알지만 "충족하는가"는 모른다. "야간근무 불가"와 "야간근무 가능자"가 가깝게 나온다. 유사도를 점수로 바꾸는 근거를 설명하기 어렵다 |
| **LLM이 전체 점수를 직접** | 같은 입력에 점수가 흔들리고, 근거가 문장뿐이라 검증할 수 없다. 가중치를 바꾸려면 프롬프트를 고쳐 다시 호출해야 한다 |
| **요건마다 LLM 1회** | 판정은 독립적이지만 호출이 요건 수만큼 늘어난다 (A는 지원자당 10회 이상). 한 번에 넣어도 요건별 출력 구조로 충분히 분리된다 |

## 결과

- 얻는 것:
  - 점수가 결정적이다 — 판정은 캐시(ADR-0014), 집계는 순수 함수. 가중치를 바꿔 다시 순위를 매길 때 LLM 호출이 없다.
  - "요건 → 판정 → 이력서 인용 → 기여 점수"로 근거를 끝까지 따라갈 수 있다.
  - 집계·규칙·검증을 LLM 없이 단위 테스트할 수 있다.
- 감수하는 것:
  - 판정 품질이 LLM에 달려 있다 → 목업 이력서에 의도한 판정을 적어 두고 일치율로 잰다 (스펙 03 실험 Y1).
  - 인용 검증은 "인용이 이력서에 있다"까지만 보장하고, "인용이 판정을 뒷받침한다"는 보장하지 않는다 → 결과 화면에 인용을 함께 보여 사람이 확인한다.

## 실험 결과 (2026-10-12, 스펙 03 Y1)

- 판정 품질을 가른 것은 모델보다 **입력 맥락과 출력 순서**였다: 근무지·평가 모집분야를 프롬프트에 넣고(둘 다 공고 이미지에서 추출한 값), 출력 스키마를 근거 → 사유 → 상태 순으로 바꾼 뒤 두 모델 모두 의도 판정 일치 93%.
- 판정 모델은 **gpt-4.1**. 일치율이 같아 오류 종류로 정했다 — 경량 모델은 근거 없는 추론("체력에 자신" → 야간근무 부분 충족)과 이력서에 없는 인용(교차 평가 9건)을 만들었다.
