# ADR-0019: API는 FastAPI로, 실행 엔드포인트는 동기로 둔다 (작업 큐 없음)

- 상태: 채택
- 날짜: 2026-10-12
- 관련 스펙: 04

## 맥락

- CLI 또는 API 엔드포인트 하나로 실행할 수 있어야 하고, UI는 API로 결과를 받는다 (ADR-0002).
- 응답 모델은 이미 pydantic이다 (`PostingCriteria`, `MatchResult`).
- 처음 처리하는 공고는 수집 + 비전 전사 + 구조화 + 판정 24회로 1~2분이 걸린다. 이미 처리한 공고는 산출물·LLM 캐시로 즉시 끝난다.
- 범위는 로컬 단일 사용자 데모다.

## 결정

1. **FastAPI** — pydantic 모델을 그대로 응답으로 쓰고(새 DTO 없음), `TestClient`로 오프라인 테스트, `/docs`에 OpenAPI 문서가 자동으로 생긴다.
2. **실행 엔드포인트(`POST /api/run`, `/match`)는 동기** — 요청이 끝날 때 결과를 돌려준다. UI는 그동안 진행 문구를 보인다.
3. 앱은 `create_app(settings, llm)` 팩토리로 만든다 — 테스트가 임시 데이터 디렉터리와 LLM 대역을 넣는다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 작업 큐 + 폴링 (`POST` → job id → `GET /jobs/{id}`) | 운영에는 맞지만, 단일 사용자 데모에서 상태 저장·정리·실패 처리 코드가 핵심 로직보다 커진다. 처음 1회만 느리고 이후는 캐시로 즉시다 |
| 진행률 스트리밍 (SSE) | 서비스의 `log` 콜백을 흘려보내면 되지만, 같은 이유로 지금은 과하다 — 확장 지점으로만 남긴다 |
| Flask | 동작은 같지만 pydantic 응답·스키마 문서를 손으로 연결해야 한다 |
| API 없이 UI가 파일을 직접 읽기 | 요구사항(API 엔드포인트로 실행)과 ADR-0002(UI는 API만)에 어긋난다 |

## 결과

- 얻는 것: 엔드포인트가 서비스 함수 호출 몇 줄로 끝난다. 응답 형식이 저장 파일 형식과 같아 CLI·API·UI가 같은 데이터를 본다.
- 감수하는 것: 처음 처리하는 공고는 요청이 1~2분 걸린다(브라우저 대기). 동시 요청이 같은 공고를 처리하면 산출물을 덮어쓸 수 있다(원자적 쓰기라 깨지지는 않음). 운영 전환 시 작업 큐로 바꾸는 지점은 `pipeline.run` 호출부 한 곳이다.
