# ADR-0020: UI는 API만 호출하는 정적 HTML 한 장으로 만든다 (빌드 없음)

- 상태: 채택
- 날짜: 2026-10-12
- 관련 스펙: 04

## 맥락

- 요구는 "매칭 결과와 근거를 보여주는 간단한 UI"다. 화려할 필요는 없다.
- 이 서비스의 핵심은 근거 추적이다: 점수 → 요건별 판정 → 이력서 인용 줄 → 공고 원본 조각 이미지. 화면이 이 연결을 클릭으로 따라가게 해야 한다.
- UI는 API를 통해서만 서비스에 접근한다 (ADR-0002).
- 실행 환경은 Python만 있으면 되도록 해 왔다.

## 결정

- `src/web/index.html` 한 파일 (HTML·CSS·바닐라 JS). `fetch`로 API를 호출하고 DOM을 직접 그린다.
- FastAPI가 같은 프로세스에서 `/`로 서빙한다 (`jobfit serve`). 외부 CDN·폰트를 쓰지 않는다 — 오프라인에서 열린다.
- 평가용 의도 라벨은 기본 숨김, 토글로 표시한다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| React/Vite 등 SPA | 화면 세 영역에 비해 Node 빌드·의존성이 크다. 실행 방법이 두 개가 된다 |
| Streamlit / Gradio | 빠르지만 Python 서비스를 **직접** 호출하는 구조라 API를 우회한다(ADR-0002 위반). 근거 표·강조 같은 맞춤 배치가 불편하다 |
| 서버 템플릿 (Jinja) | 가능하지만 가중치 슬라이더 재랭킹처럼 즉시 반응하는 부분은 어차피 JS가 필요하다 |

## 결과

- 얻는 것: `jobfit serve` 하나로 API·UI가 뜬다. UI가 API의 첫 번째 사용자라 API 형식이 실제로 쓸 만한지 검증된다.
- 감수하는 것: 화면 로직이 한 파일에 모여 커질 수 있다(목표 500줄 이하). 컴포넌트 재사용·테스트는 없다 — UI는 수동 확인한다.
