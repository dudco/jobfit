# ADR-0021: 단계별 명령은 그대로 두고, 한 번에 실행하는 `run`을 위에 얹는다

- 상태: 채택
- 날짜: 2026-10-12
- 관련 스펙: 04

## 맥락

- 요구: "공고 크롤링 → 이미지 파싱 → 추출값을 조건으로 바로 세팅 → 매칭 스코어링"이 CLI 또는 API 엔드포인트 하나로 실행돼야 한다.
- 지금은 단계마다 명령이 있다 (`crawl`, `extract`, `match`). 단계별 명령은 실험·디버깅에 필요했다 (스펙 02·03의 실험은 단계 하나만 다시 돌렸다).
- 각 단계는 산출물이 있으면 재사용한다 (ADR-0005, 0014).

## 결정

- `pipeline.run(ref, …)`이 `crawl → extract → match`를 순서대로 호출한다. 단계 사이에 사람이 손대는 지점이 없다 — 추출한 조건이 그대로 매칭 조건이 된다.
- CLI `jobfit run`과 API `POST /api/run`이 이 함수 하나를 호출한다.
- `--refresh`는 **매칭만** 다시 한다. 수집·추출을 다시 하려면 단계별 명령의 `--refresh`를 쓴다 — 공고는 마감되면 사라지므로 한 번에 실행에서 원본 스냅샷을 실수로 덮어쓰지 않게 한다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 단계별 명령만 두고 문서로 순서 안내 | 요구사항(하나로 실행)을 만족하지 않는다 |
| 단계별 명령을 없애고 `run`만 | 실험·디버깅 때 한 단계만 다시 돌릴 수 없다 |
| `--refresh`를 모든 단계에 전파 | 마감된 공고의 원본을 다시 받을 수 없어 스냅샷을 잃을 수 있다 |

## 결과

- 얻는 것: 새 공고 URL 하나로 끝까지 실행된다. 같은 공고를 다시 실행하면 캐시로 즉시 끝난다.
- 감수하는 것: 단계 하나가 실패하면 그 뒤는 실행되지 않는다 (앞 단계 산출물은 남아 있어 다시 실행하면 이어서 진행).
