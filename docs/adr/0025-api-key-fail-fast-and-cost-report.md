# ADR-0025: API 키가 없으면 작업 전에 멈추고, 사용량은 캐시 파일에 함께 기록한다

- 상태: 채택
- 날짜: 2026-10-12
- 관련 ADR: [0014](0014-llm-response-cache.md) (응답 캐시 — 일부 대체), [0024](0024-judge-model-cascade-experiment.md)

## 맥락

- 키 없이 `extract`·`match`·`run`을 실행하면 캐시에 없는 첫 호출에서야 OpenAI SDK 예외가 난다. 수집·조각 처리 같은 앞 단계가 이미 돈 뒤라 원인이 늦게, 추적 정보와 함께 보인다.
- ADR-0014는 "캐시 적중이면 키 없이도 동작"을 장점으로 두었지만, 어느 호출이 캐시에 있는지 사용자는 알 수 없다 — 같은 명령이 어떤 때는 되고 어떤 때는 중간에 실패한다.
- 실험(모델 비교·JEV)을 거치며 지금까지 쓴 API 비용을 묻게 됐는데, 기록이 없었다.

## 결정

1. **키 확인을 작업 앞에 둔다.** OpenAI를 쓸 수 있는 명령(`extract`, `match`, `run`, `models`)과 API(`POST …/match`, `POST /api/run`)는 `OPENAI_API_KEY`, `experiment-jev`는 `TYPESAFE_API_KEY`가 비어 있으면 바로 멈춘다 — CLI는 한 줄 안내와 종료 코드 1, API는 400. 키가 필요 없는 명령(`crawl`, `postings`, `criteria`, `result`, `evaluate`, `cost`, `serve`, 화면의 가중치 재집계)은 그대로다.
2. **캐시 파일에 사용량을 함께 남긴다.** 응답의 `usage`(입력·캐시된 입력·출력 토큰)를 캐시 파일의 `usage`에 기록한다. 캐시 파일 하나 = 실제 호출 하나이므로, 캐시 디렉터리가 곧 호출 기록이다.
3. **`jobfit cost`로 집계한다.** 모델 × 단계(전사·구조화·판정·JEV 판정)별 호출 수·토큰·비용. 가격표는 `src/usage.py`의 `PRICES` 한 곳.
4. 사용량 기록 이전 호출은 **추정**으로 따로 표시한다: 남아 있는 재료(조각 이미지 크기, 전사, 이력서·요건)로 프롬프트를 다시 만들어 토큰을 센다 (이미지는 OpenAI 타일 규칙, 글자는 영문 4자·한글 1.5자당 1토큰).

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 지금처럼 첫 호출에서 실패 | 앞 단계가 돈 뒤에야, SDK 예외로 실패 |
| 캐시에 다 있으면 키 없이 허용 (사전 점검) | 캐시 키가 프롬프트 전체 해시라 점검하려면 단계를 거의 다 실행해야 한다 |
| 별도 사용량 로그 파일 | 캐시와 어긋날 수 있다. 캐시 파일 = 호출 하나라는 대응이 이미 있다 |
| OpenAI 사용량 대시보드·API | 조직 단위라 이 프로젝트 호출만 가를 수 없고, 관리자 키가 필요 |

## 결과

- 얻은 것: 키 문제는 실행 즉시 한 줄로 알 수 있다. 비용을 단계·모델별로 볼 수 있다 (2026-10-12 기준 254회, 약 $1.32 — 대부분 추정).
- 감수할 것: 캐시만으로 재생하던 오프라인 실행도 키가 있어야 한다 (테스트는 대역을 주입하므로 영향 없음). 집계는 **남아 있는 캐시 파일 기준의 하한**이다 — 실패한 호출, `--refresh`로 같은 키를 덮어쓴 호출, 지운 캐시는 세지 않는다. 가격이 바뀌면 `PRICES`를 고쳐야 한다.
