# 설계 결정과 트레이드오프 — 요약 자료

README의 "설계 결정과 트레이드오프"를 쓰기 위한 자료다. 결정마다 근거·대가·실험 수치와 상세 문서(ADR·스펙)를 모았다. README 본문은 이 자료를 바탕으로 직접 쓴다.

## 1. 문제를 어떻게 나눴나

| 결정 | 이유 | 대가 | 문서 |
|---|---|---|---|
| 수집 → 전처리·구조화 → 스코어링 3단계, 단계 사이 계약은 파일 산출물 | 단계마다 실험·검증을 따로 할 수 있다. 수집을 고객사 업로드로 바꿔도 뒤 단계는 그대로 | 파일 형식을 바꾸면 여러 단계를 고쳐야 한다 | ADR-0001, 0005 |
| CLI·API·UI는 같은 서비스 함수를 부르는 얇은 어댑터 | 로직이 한 곳. UI가 API의 첫 사용자 | 진입점별 맞춤 기능은 서비스에 먼저 넣어야 한다 | ADR-0002 |
| 매칭 조건은 공고 **이미지**에서만 (페이지 숨김 키워드·HTML 텍스트 미사용) | 과제의 "이미지 파싱 결과가 입력" 요구. 숨김 SEO 키워드는 공고 작성자가 쓴 조건이 아니다 | 이미지에 요건이 없는 공고는 평가할 수 없다 → 별도 목록으로 (ADR-0023) | ADR-0008 |

## 2. 이미지에서 조건 뽑기

| 결정 | 이유 | 대가 | 수치 | 문서 |
|---|---|---|---|---|
| OCR+규칙 대신 비전 LLM | 장식 폰트·표·병합 셀. 규칙은 공고마다 늘어난다 | 비결정성·외부 의존 → 근거 인용 검증, 응답 캐시 | | ADR-0010 |
| 읽기(전사)와 이해(구조화)를 나누고 코드로 검증 | 틀렸을 때 "잘못 읽었나 / 잘못 해석했나"를 구분. 전사가 근거 인용의 원문 | 호출 1회 추가 | 인용 검증 실패 0건 (이어 붙인 인용 2건은 `quote_spliced`로 인정) | ADR-0011 |
| 긴 이미지는 글자 줄 사이 여백에서 1200px로 자름 | 통째로 넣으면 축소돼 **없는 문장을 생성**, 800px는 표 행을 잘라 줄이 사라짐 | 조각 수만큼 호출 | 통째 S-OIL 재현율 58% → 1200px 분할 후(보정 포함) 100% | ADR-0012 |
| 구조화 모델 gpt-4.1 (mini 아님) | mini는 유의사항의 우대 문구를 놓치고 인용을 바꿔 씀 | 비용 (공고당 1회라 작음) | 재현율·정밀도 100% (정답 18개) | ADR-0010 |
| 요건 = 고정 유형 8개 + 모집분야 범위 + 필수/우대 | 직군을 하드코딩하지 않는다. 새 직군은 데이터만 다르다 | 유형 경계가 모호한 요건이 있다 | | ADR-0013 |

## 3. 지원자와 맞추기

| 결정 | 이유 | 대가 | 수치 | 문서 |
|---|---|---|---|---|
| LLM은 요건별 **판정**만, 점수는 코드가 계산 | 같은 입력에 같은 점수. 기여 점수의 합 = 총점으로 설명. 가중치를 바꿔도 재호출 없음 | 판정 품질이 LLM에 달림 → 의도 판정 일치율로 측정 | 의도 판정 일치 93% (38/41) | ADR-0015 |
| 판정에는 이력서 **인용**이 필수, 인용이 없으면 "확인 필요"로 내림 | 환각 방어. 사람이 근거를 따라갈 수 있다 | 인용 표기 차이로 오탐 → 대괄호·콜론 무시 | 인용 검증 실패 0건 | ADR-0015 |
| 학력 서열·경력 연수는 코드 | LLM에게 산수를 시키지 않는다 | 규칙이 다루지 못하는 조건(전공·기한)은 LLM | | ADR-0015 |
| 점수 = (필수 평균 × 0.7 + 우대 평균 × 0.3) × 0.8^(필수 미충족 수) | 필수만 다 갖추면 70점. 필수 하나 미충족으로 0점이 되지 않게(판정 오류에 강함) | 상수는 근거가 약함 — 목업 12명의 의도 구간으로만 확인 | 완벽 93~100, 부분 52~78, 미스매치 28~34 | ADR-0017 |
| "모름"(확인 필요)은 0.5점, 감점 배수 없음 | 이력서에 잘 안 쓰는 자격("해외여행 결격사유 없음") 때문에 모두가 깎이지 않게. 면접 확인 항목으로 따로 보여줌 | 정보가 적은 이력서가 유리해질 여지 → 0점도 1점도 아닌 절반 | | ADR-0017 |
| 법정 우대(보훈·장애인)는 점수 미반영, 이력서에서 받지 않음 | 법령·증빙으로 전형에서 적용하는 가점. 민감 정보 | 실제 전형 순위와 다를 수 있음 → 화면에 명시 | | ADR-0018 |
| 직무 요건이 없는 공고만 모집분야 이름에서 "직무 적합도" 우대 요건 도출 | 공통 자격만 있으면 전원 같은 점수 | "공고에 명시된 것만" 원칙의 예외 — 표시·끄기 가능 | KT&G: 11명 동점 → 점수 5단계로 분리 | ADR-0022 |

## 4. 평가를 어떻게 했나

- **정답을 먼저 만들고 잰다**: 공고 이미지를 보고 사람이 정답 요건 18개를 만들고 재현율·정밀도를 쟀다 (스펙 02). 목업 이력서마다 "의도한 판정"을 적어 두고 일치율을 쟀다 (스펙 03).
- **목업 12명은 각자 다른 이유로 점수가 갈리게**: 같은 단어 / 다른 표현 / 기한 초과 / 인접 전공 / 확인 필요 / 키워드 나열 / 학력 서열. 라벨은 평가 전용 — 점수 계산은 읽지 않는다 (테스트로 보장).
- **교차 평가**: 12명 전원을 두 공고에 매칭. S-OIL 미스매치(화학공장 생산직 10년)가 오리온 생산직에서 85점 — 점수가 라벨이 아니라 요건으로 매겨진다.
- **테스트는 원칙이 깨지면 실패하는 것만**: 기여 합 = 점수, 인용 검증, "모름 ≠ 없음", 라벨을 바꿔도 점수 불변, 법정 우대가 LLM에 가지 않음, 코드에 없는 직군(바리스타)도 동작, 텍스트 공고는 추출로 넘어가지 않음 등. 네트워크·API 키 없이 174개.

## 5. 과제하면서 발견한 것 (README "생각" 후보)

- **LLM이 틀린 곳은 대부분 "읽기"가 아니라 "맥락"이었다.** 판정 LLM이 근무지를 몰라 울산 거주자를 청주 인근거주로, 지원 분야를 몰라 설비 지원자를 "엔지니어 지원자 아님"으로 판정했다. 이미 추출한 값(근무지·모집분야)을 넘겨주자 해결 (스펙 03 Y1).
- **출력 스키마의 필드 순서가 판정을 바꿨다.** 상태를 사유보다 먼저 생성하게 하자 "졸업 기한을 충족하지 못한다"고 쓰고 상태는 "충족"을 줬다. 근거 → 사유 → 상태 순서로 바꿔 해결.
- **통째로 넣은 고해상도 이미지에서 LLM이 없는 문장을 지어냈다.** 분할이 정확도 문제이기 전에 환각 문제였다.
- **경량 모델과 상위 모델의 일치율이 같아도 오류의 종류가 달랐다.** mini는 "체력에 자신 있음"으로 야간근무를 추론했다 — 일치율만 보고 고르면 "근거 없는 추론"을 놓친다.
- **"모름"과 "없음"을 나누는 것이 설계의 중심이 됐다.** 이력서에 없는 정보, 공고에 없는 요건, 이미지에 없는 공고 — 각각 점수 0이 아니라 "확인 필요", "정보 부족 안내", "처리하지 않은 공고"로 따로 드러냈다.
- **판단 전용 모델은 "판정만" 시키면 압도적으로 빠르다.** 같은 판정을 JEV로 바꾸자 공고 2개 × 12명이 1분 20초에서 5초대로 줄었다. 개별 판정은 52~83%만 일치했지만 지원자 순위는 0.91~0.97로 거의 같았다 — "정확한 근거"와 "빠른 순위"를 나눠 맡기는 구조(1차 선별 → 상위 K명 정밀 판정)가 자연스럽다. 판정과 점수 계산을 분리해 둔 덕분에(ADR-0015) 판정 모델만 바꿔 끼우는 실험이 코드 몇 줄로 가능했다.
- **목업 데이터의 모호함도 결과에 드러난다.** 카페 바리스타를 "생산 경험 없음"으로 의도했지만 LLM은 식품 취급 경험으로 봤다 — 판정이 아니라 의도가 모호했다. 판정이 의도와 다르다는 이유만으로 데이터를 고치지 않았다.

| 데이터 유입 | 사람인 데모 수집기 | 고객사 경유 (업로드·브라우저 확장·ATS) — [data-ingestion-via-customers.md](data-ingestion-via-customers.md) |
| 이력서 형식 | 목업 JSON = 이력서 전처리 결과 | 형식별 추출 → 구조화 → 검증 (ADR-0016) |
| 지원자 규모 | 12명, 지원자당 판정 1회 | 수천 명이면 임베딩 검색으로 후보를 추린 뒤 상위 K명만 판정 |
| 판정 속도·비용 | gpt-4.1 지원자당 약 3초·$0.0125 (공고 2개 × 12명: 약 1분 20초, $0.30) | 판단 전용 모델(JEV) 실험: 같은 작업 **약 5.5초(15배)·$0.0064(47배)**, 순위 상관 0.91~0.97 — 지원자가 많으면 JEV로 전원을 몇 초 안에 1차 선별하고 상위 K명만 gpt-4.1로 근거까지 판정 (ADR-0024, 스펙 06) |
| 실행 | 동기 요청 (처음 1~2분) | 작업 큐 + 진행률 (ADR-0019) |
