# 06. 판단 전용 모델(JEV) 판정 실험 설계

- 날짜: 2026-10-12
- 상태: 완료 (2026-10-12) — 기본 판정 교체·지원자 단위 단계식은 채택하지 않음, 대규모 1차 선별 용도로 권장
- 단계: ③ 스코어링 (실험 — 기본 판정 경로는 바꾸지 않음)
- 구현 계획: [plans/2026-10-12-06-judge-model-experiment.md](../plans/2026-10-12-06-judge-model-experiment.md)
- 관련 ADR: [0024](../adr/0024-judge-model-cascade-experiment.md) (제안), [0015](../adr/0015-judge-then-aggregate.md)

## 1. 질문

요건별 판정(요건 × 이력서 → 충족/부분/미충족/확인 필요/해당 없음)은 정해진 선택지에서 고르는 일이다. 글을 생성하지 않고 선택지 확률만 돌려주는 **판단 전용 모델**(TypeSafe JEV)로 이 판정을 대신하거나, 확신도가 높은 판정만 맡기고 나머지를 gpt-4.1로 넘기면(단계식 판정) 품질을 유지하면서 비용·지연을 줄일 수 있는가?

공개 자료의 주장: 1,000건당 약 $0.044(입력 토큰 100만 개당 $0.042, 출력 무료), 응답 0.07~0.5초. 글에서 읽어낼 수 있는 판정은 상위 LLM과 비슷하지만 전문 지식 판단은 7~28점 뒤처짐. 한국어 지원은 문서에 없다.

## 2. 설계

### 2.1 질문 구성 (지원자 × 공고당 1회 호출)

| 질문 ID | 종류 | 선택지 |
|---|---|---|
| `{요건}__status` | Choice | met · partial · unmet · unknown · not_applicable (판정 기준은 LLM 판정과 같은 정의) |
| `{요건}__evidence` | Choice | 이력서 줄 `L01`…`Lnn`(줄 내용이 설명) + `none` |

- `state` = `{posting: 공고 제목·직군·근무지·평가 모집분야, resume: 줄 번호 이력서}` — LLM 판정과 같은 맥락 (스펙 03 Y1 진단 1·2).
- **근거 인용은 고른 줄의 원문**이다 → 이력서에 없는 인용이 구조적으로 생길 수 없다. 근거 줄이 `none`인데 충족·부분·미충족이면 기존 검증대로 확인 필요(`no_evidence`)로 내려간다.
- 사유 문장은 없다 — "JEV 판정 (확신도 0.93)"만 남는다.
- 답을 LLM 판정과 같은 형식(`LLMJudgeOutput`)으로 바꿔 **검증·학력/경력 규칙·집계·분야 선택을 그대로** 쓴다 (`score_candidate(judge_fn=…)`).

### 2.2 비교

| 지표 | 정의 |
|---|---|
| 기준과 일치 | 같은 (지원자, 요건)에서 JEV 판정 상태 = gpt-4.1 판정 상태 (저장된 매칭 결과가 기준) |
| 의도 판정 일치 | 목업 `meta.expected`와의 일치 (스펙 03의 지표) |
| 의도 순서·구간 | 완벽 > 부분 > 미스매치, 점수 구간 (스펙 03 수용 기준) |
| 점수 순위 상관 | JEV 점수와 gpt-4.1 점수의 스피어만 상관 |
| 근거 없는 판정 | 충족·부분·미충족인데 근거 줄을 `none`으로 고른 수 |
| 단계식 판정 | 확신도 기준 t마다: 지원자의 판정 중 하나라도 확신도 < t면 그 지원자를 gpt-4.1로 넘김(판정이 지원자 단위 호출이므로). 넘긴 수, 기준과 일치, 의도 판정 일치, 추정 비용 (JEV 실제 토큰 + 넘긴 지원자 × $0.0125) |
| 비용·지연 | 입력 토큰, 응답 시간 중앙값 |

대상: S-OIL(55189170), 오리온(55162188), KT&G(55240124, 의도 라벨 없음 — 기준과 일치·분야 선택만).

### 2.3 판단 기준 (실험 후)

- **대체**: JEV 단독이 의도 판정 일치 ≥ 90%, 의도 순서·구간 유지, 근거 없는 판정이 적음.
- **단계식**: 어떤 t에서 기준과 일치 ≥ 95%, 의도 판정 일치가 gpt-4.1과 같고, 넘긴 비율 ≤ 50%.
- 둘 다 아니면 **채택하지 않음** — 확장 방향으로만 기록.
- 한국어 판정 품질은 위 지표로 함께 본다.

## 3. 구현

| 모듈 | 내용 |
|---|---|
| `scoring/jev.py` | 질문 구성, 답 → `LLMJudgeOutput` 변환, 응답 디스크 캐시(`data/cache/jev/`) |
| `scoring/experiment_jev.py` | 실험 실행·지표 계산, `data/experiments/jev-{공고}.json` 저장 — `ranking.json`은 바꾸지 않음 |
| `scoring/service.py` | `score_candidate(judge_fn=…)` — 판정 방식을 바꿔 끼우는 자리 |
| `cli.py` | `jobfit experiment-jev <rec_idx>... [--thresholds]` |
| `pyproject.toml` | 선택 의존성 `[jev]` = `typesafe-sdk` |

API 키는 `.env`의 `TYPESAFE_API_KEY` (커밋하지 않음). 모델은 `JOBFIT_JEV_MODEL`(기본 `jev-latest`, 결과에 실제 버전 기록).

## 5. 관찰 기록

### 실험 결과 (2026-10-12, jev-1.13.0, 기준 = 저장된 gpt-4.1 판정)

#### 속도·비용 — 가장 큰 차이

| | gpt-4.1 판정 | JEV 판정 | 차이 |
|---|---|---|---|
| **공고 2개(S-OIL·오리온) × 지원자 12명 = 24회** | **약 1분 17초~1분 29초** (사용자 실행 3회 기록) | **약 5.5초** (API 응답 합계, 호출당 중앙값 0.21~0.23초) | **약 15배 빠름** |
| KT&G × 12명 (요건 31개, 질문 62개) | 약 1분 34초~2분 16초 | 약 4.7초 (호출당 중앙값 0.40초) | 약 20~29배 |
| 세 공고 전체 36회 | 약 3~4분 | **11초** (명령 전체 실행 시간) | |
| 비용 — 공고 2개 × 12명 | 약 $0.30 | **$0.0064** (입력 15만 토큰) | 약 47배 저렴 |
| 비용 — KT&G × 12명 | 약 $0.15~0.4 | $0.015 (입력 36만 토큰) | |

- 두 방식 모두 지원자당 1회를 **차례로** 호출한 시간이다. 동시 호출을 쓰면 둘 다 더 줄지만, JEV는 호출 하나가 0.2~0.4초라 수천 명도 실시간에 가깝게 처리할 수 있는 규모다 — 화면에서 "공고를 넣고 몇 초 안에 랭킹"이 가능해진다.
- 처음 처리하는 공고의 체감 대기(스펙 04: 1~2분)의 대부분이 판정이므로, 판정을 JEV로 바꾸면 매칭 단계는 몇 초로 줄어든다.

#### 품질

| 공고 | 판정 수 | gpt-4.1과 일치 | 점수 순위 상관 | 의도 판정 일치 (gpt / JEV) | 의도 순서·구간 (JEV) | 근거 없는 판정 | 확신도 중앙값 |
|---|---|---|---|---|---|---|---|
| S-OIL | 113 | 76% | 0.91 | 20/22 / **21/22** | ✗ — soil-partial-2 100점 | 6 | 0.81 |
| 오리온 | 48 | 83% | 0.97 | 18/19 / 17/19 | ✓ | 7 | 0.88 |
| KT&G | 372 | 52% | 0.92 | — (의도 라벨 없음) | ✓ | **294** | **0.36** |

- **잘한 곳**: 영어 회화(OPIc AL·교환학생) 충족, 병역 "비대상" → 해당 없음 — 목업 의도와 gpt-4.1보다 더 맞았다. 다른 직군 지원자의 전공 요건을 "해당 없음"이 아니라 "미충족"으로 본 것도 의도에 가깝다.
- **틀린 곳 — 기한 단서**: 졸업 예정 2027-08을 "2027년 2월 이내 졸업 예정"의 **충족**으로 판정 (확신도 0.85). gpt-4.1의 1차 실행과 같은 실패이고, 확신도가 높아 단계식으로도 걸러지지 않는다 (0.9 기준에서만 넘어감).
- **보수적인 곳 — 인접 경험**: "해당직무 근무경험"을 물류·카페·마트 경험에 대해 대부분 확인 필요로 판정 (gpt-4.1은 부분·미충족).
- **약한 곳 — 모집분야 적합도(도출 요건)**: KT&G에서 "이 배경이 '시장개척 지원'과 관련 있나" 같은 판정의 확신도가 낮고(중앙값 0.36), 근거 줄을 대부분 고르지 못했다(294건). 공개 자료의 "전문 지식이 필요한 판단에서 뒤처짐"과 같은 결과.
- 그런데도 **지원자 순위는 gpt-4.1과 강하게 상관**(0.91~0.97)한다 — 개별 판정은 갈려도 누가 위·아래인지는 대체로 같다.

#### 단계식 판정 (확신도 낮은 판정이 있는 지원자를 gpt-4.1로)

| 공고 | 기준과 95% 이상 일치하는 최저 기준 | 그때 넘긴 지원자 | 의도 판정 일치 | 추정 비용 |
|---|---|---|---|---|
| S-OIL | 0.5 (96%) | 8/12 (67%) | 21/22 (0.7에서 22/22) | $0.104 |
| 오리온 | 0.7 (96%) | 7/12 (58%) | 18/19 | $0.089 |
| KT&G | — | 모든 기준에서 12/12 | — | $0.165 |

지원자 단위로 넘기면, 지원자 한 명의 판정 10~30개 중 하나만 불확실해도 그 지원자 전체를 gpt-4.1로 다시 판정해야 해서 넘기는 비율이 높다.

### 판단 (2.3 기준)

- **대체: 아니오** — S-OIL 의도 순서 깨짐(기한 단서를 높은 확신도로 틀림), 오리온 의도 판정 17/19(89%) < 90%.
- **지원자 단위 단계식: 아니오** — 95% 일치를 맞추면 넘기는 비율이 58~100%로 50%를 넘는다.
- **대신 권장: 대규모 1차 선별** — 순위 상관 0.91~0.97과 15배 이상의 속도·약 47배 낮은 비용이면, 지원자가 많을 때 JEV로 전원을 몇 초 안에 판정해 상위 K명을 추리고, 그 K명만 gpt-4.1로 근거·사유까지 판정하는 구성이 맞다. 상위권 순위가 흔들리지 않는지는 지원자 풀이 큰 데이터로 다시 재야 한다 (목업 12명은 작다).
- 개선 여지: (1) 요건 단위로만 넘기기 — 불확실한 요건만 gpt-4.1에 물으면 넘기는 양이 줄어든다(호출 수는 그대로). (2) 기한·숫자 비교 같은 조건은 코드 규칙으로 — 학력 서열처럼 "졸업 예정 시점 ≤ 기한"을 규칙으로 옮기면 두 모델 모두의 같은 실패가 사라진다.
